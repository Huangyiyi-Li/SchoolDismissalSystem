# 教师端放学管理空状态设计

## 1. 背景与目标

教师端“放学管理”页面目前已有正常态，但缺少以下两种业务空状态：

1. 当前教师没有任何班级管理权限。
2. 当前学校尚未设置放学时间。

本次仅补充小程序端页面原型与业务规则说明，不修改正常态，不设计后台接口、数据表或生产代码。

## 2. 设计原则

- 采用页面级空状态，避免残留的日程卡片或操作按钮让教师误以为仍可发起放学。
- 沿用参考页面的绿色导航栏、浅灰背景、白色圆角卡片和移动端间距节奏。
- 两种空状态复用同一套插图和排版，只替换标题与说明文案。
- 空状态仅用于信息告知，不提供刷新、跳转、拨号或其他交互。
- 客服热线 `12556166` 以普通文本展示，不渲染为链接或按钮。

## 3. 页面状态

### 3.1 无班级权限

#### 触发条件

当前登录教师没有任何可管理班级。

#### 页面结构

- 保留顶部绿色导航栏及标题“放学管理”。
- 隐藏班级信息栏。
- 隐藏“今日放学日程”和“待开启放学”等业务模块。
- 主内容区显示居中的空状态卡片。

#### 展示文案

- 标题：`暂无可管理班级`
- 说明：`当前账号尚未关联可管理的班级，请联系学校管理员开通权限。`
- 客服：`如需帮助，请联系客服电话：12556166`

### 3.2 学校未设置放学时间

#### 触发条件

当前教师至少拥有一个可管理班级，但学校没有可用的放学时间配置。

#### 页面结构

- 保留顶部绿色导航栏及标题“放学管理”。
- 保留当前班级信息栏。
- 隐藏“今日放学日程”和“待开启放学”等业务模块。
- 主内容区显示居中的空状态卡片。

#### 展示文案

- 标题：`暂未设置放学时间`
- 说明：`学校尚未配置放学时间，请联系学校管理员完成设置。`
- 客服：`如需帮助，请联系客服电话：12556166`

## 4. 状态判定优先级

页面按以下顺序判定并展示：

1. 当前教师无可管理班级时，展示“无班级权限”。
2. 当前教师有可管理班级、但学校无可用放学时间配置时，展示“学校未设置放学时间”。
3. 班级和放学时间配置均可用时，展示现有正常态。

因此，当两个异常条件同时存在时，“无班级权限”优先。

## 5. 原型范围与评审方式

- 交付一个可离线打开的单 HTML 文件。
- 仅包含小程序端视觉，不提供 PC 或 APP 平台切换。
- 原型外层提供“无班级权限 / 未设置放学时间”评审状态切换，以便在同一文件中查看两种状态。
- 评审状态切换不属于手机页面内容，生产页面中不得出现。
- 使用 ThorUI 风格的 `tui-*` 语义类表达移动端组件。
- 文件内附带可编辑的业务规则检查器，覆盖页面框架、班级信息和两种空状态。

## 6. 业务规则标注范围

| 规则上下文 | 说明 |
|---|---|
| 小程序页面框架 | 导航栏、页面背景及移动端安全区规则 |
| 班级信息 | 仅在教师拥有可管理班级时展示 |
| 无班级权限空状态 | 触发条件、隐藏内容、固定文案及无交互约束 |
| 未设置放学时间空状态 | 触发条件、保留内容、固定文案及无交互约束 |

规则说明只描述业务定义、展示条件、状态优先级和验收要求，不扩展为接口或数据存储设计。

## 7. 验收标准

- 可在同一个离线 HTML 中分别查看两种空状态。
- “无班级权限”状态不展示班级信息、放学日程或放学操作。
- “未设置放学时间”状态展示班级信息，但不展示放学日程或放学操作。
- 两种状态均显示客服电话 `12556166`，且不存在按钮、链接或拨号行为。
- 两种状态的标题、说明文字与本设计文档一致。
- 页面视觉与参考图保持同一设计语言，并适配手机安全区。
- 规则检查器默认隐藏，支持规则增删改、排序、本地保存、恢复初始内容及导出最新版 HTML。
- 最终 HTML 不包含远程依赖，规则上下文完整且无孤立规则。
