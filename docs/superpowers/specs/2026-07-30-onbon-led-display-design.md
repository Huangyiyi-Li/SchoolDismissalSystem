# 仰邦 BX-6E1XP 放学状态屏设计

## 范围

- 控制卡：BX-6E1XP，网线控制，无通信密码。
- 屏幕：1024 × 96，单基色。
- 客户端使用 Java SDK `BX_05_06_SDK_20241105` 的六代控制卡库。
- Python 主程序负责班级数据、状态和图片生成；Java Bridge 负责调用仰邦 SDK。

## 班级口径

- LED 只展示服务端班级接口实际返回的行政班（`classType=1`）。
- 不补齐、猜测或生成服务端没有返回的班级。
- 同一 `classId` 即使关联多个卡号，在 LED 中也只显示一次。
- 按服务端返回的 `gradeName` 分组，组内保持服务端返回顺序。
- 每页各年级共用列数，列数取全部年级中实际班级数的最大值；班级较少的年级右侧留空。

## 画面与翻页

- 每张图片固定为 1024 × 96 单色位图。
- 每页显示两行年级；年级超过两行时生成多张图片，由控制卡循环翻页。
- 顶部显示班级序号，左侧显示学校标题和年级名称，单元格显示班级状态。
- 单基色屏不使用颜色表达业务状态：空白表示未触发，`放学中` 和 `已放学` 使用文字区分。
- 当前刷卡和手动放学事件将班级设为 `放学中`；`已放学` 作为明确接口保留，待服务端提供完成事件后接入。

## 通信与容错

- 控制卡 IP、端口、学校标题和翻页停留时间可在软件中修改并持久化。
- 默认 IP 为 `192.168.100.1`，默认端口为仰邦 SDK 示例使用的 `5005`。
- Java Bridge 使用一个覆盖全屏的动态区（ID 0）推送多张图片，循环播放。
- LED 通信在后台执行；连接或推送失败只记录错误，不阻断原有语音播报和服务端推送。
- 设置页提供连接测试和测试画面推送。

## 验收

1. 同一班级多个卡号只出现一个格子。
2. 服务端未返回的班级不会出现。
3. 5 个年级时生成 3 张 1024 × 96 图片并循环显示。
4. 刷卡和服务端手动放学均触发对应班级 `放学中`，且 LED 失败不影响原链路。
5. 修改控制卡 IP 后重启软件仍保留。
6. Windows 公司电脑可通过“测试连接”和“发送测试画面”验证真实 BX-6E1XP。
