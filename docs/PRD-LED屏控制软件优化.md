# LED 屏控制软件优化 PRD

## 1. 文档信息

- 产品：数智家校放学系统 - LED 屏控制模块
- 版本：优化版 beta.9
- 日期：2026-08-06
- 适用设备：仰邦 BX-6E1XP，单色/双色，网线控制

## 2. 背景与问题

系统已能够通过 Java SDK 控制仰邦 LED 控制卡，展示学校、年级、班级及放学状态。现场测试发现：

1. 开启测试模式后，LED 屏没有立即切换到放学信息。
2. 软件重启后，已经放学的班级状态丢失。
3. LED 屏版式固定为两个年级一屏，无法适配不同学校的年级数量和屏幕展示需求。
4. 到达放学时段时，若首次 LED 下发失败，可能要等待后台同步后才重新出现放学节目。
5. 现场测试依赖真实刷卡，缺少可选择班级并同时验证语音与 LED 的模拟入口。

## 3. 产品目标

- 测试模式能够立即验证完整的 LED 放学展示链路。
- 放学期间软件重启后，班级状态能够恢复，避免现场状态中断。
- 管理员可以按学校实际情况配置每屏展示的年级数量。
- 非放学时间不持续控制 LED 屏，并恢复控制卡原有节目。
- 到达放学时段后自动激活 LED；首次发送失败时自动重试。
- 在测试模式下支持模拟指定班级刷卡，验证语音、状态和 LED 全链路。
- 支持行政班与社团班、正式状态与测试状态隔离。
- 支持手动像素尺寸、1–6 个横向分区、标题开关及本地同源预览。
- 支持单色/双色屏配置，并用双色屏的红、黄、绿区分三种放学状态。

## 4. 功能需求

### 4.1 测试模式控制 LED

- 用户在主界面开启“测试模式”后，LED 屏立即进入放学信息展示状态。
- 测试模式下刷卡只进行本地播报，不推送服务端；LED 屏仍可用于现场画面验证。
- 进入测试模式后显示空白测试状态，正式放学状态继续保留；退出测试模式后恢复正式状态。
- 用户关闭测试模式后：
  - 若当前处于行政班放学时段，继续展示放学信息。
  - 若当前不在放学时段，停止动态画面并恢复原节目。

### 4.2 班级状态持久化

- 班级状态包括：`放学中`、`已放学`。
- 状态按“学校 + 班级 + 日期”保存到本地数据库。
- 软件重启时恢复当天状态：
  - `已放学`直接恢复。
  - `放学中`恢复剩余倒计时，到期后自动变为`已放学`。
- 进入新的一天后，自动清理前一天状态。
- 点击“清空状态/恢复原节目”时，清除当天状态并恢复原节目。
- 换绑学校时，只清理原学校状态，不影响其他学校数据。

### 4.3 LED 版式与尺寸配置

设置页提供以下配置：

- 手动填写屏幕像素宽度和高度；尺寸由学校施工方确认，软件不自动读取。
- 尺寸只允许正整数：宽度不超过 `2048`、高度不超过 `1024`；单色总像素不超过 `524288（512K）`，双色不超过 `262144（256K）`；软件不强制 8/16/32 倍数。
- 行政班横向分区数、每区年级行数分别取值 `1–6`。
- 社团班横向组数、每组社团行数分别取值 `1–6`，与行政班布局独立保存。
- 内容按服务端顺序先填满左区，再依次填入右侧区域；超过容量后生成下一页。
- “显示左侧标题”关闭后，标题区域完全释放给班级内容。
- 原有配置继续保留：控制卡 IP、端口、学校标题、翻页间隔、放学延迟。

### 4.4 行政班与社团班

- 班级目录、状态持久化、刷卡、模拟刷卡和 LED 展示同时支持行政班与社团班。
- 行政班按年级和班级序号展示。
- 社团班每组分为“社团名/状态”两列；状态列固定单行，空白表示未放学，长社团名自动缩小并最多分两行。
- 两类放学时段重叠时生成独立页面并按翻页间隔轮播。
- 状态按“学校 + 班级类型 + 班级 + 日期”隔离，避免相同班级 ID 冲突。

### 4.5 到点激活与失败重试

- 软件每秒判断行政班放学时段，到达开始时间后立即激活放学节目。
- 首次发送失败时，每 10 秒自动重试一次；发送成功后停止重试。
- LED 发送失败不影响刷卡、语音播报及其他业务。

### 4.6 模拟刷卡

- 主界面增加“模拟刷卡”按钮，仅在测试模式开启时可用。
- 点击后从已同步的行政班和社团班目录中选择一个班级。
- 确认后执行与真实刷卡一致的本地效果：语音播放、LED 状态变为“放学中”，并在设置的延迟后变为“已放学”。
- 模拟刷卡不调用服务端放学状态接口，操作结果写入本地实时日志并标记为“模拟刷卡”。

### 4.7 LED 内容预览

- 设置窗口提供与真实 LED 图片共用渲染器的本地预览，不连接或发送控制卡。
- 参数变化后不自动重绘；用户点击“生成预览/重新生成预览”后在后台生成，支持上一页、下一页和页数显示。
- 参数修改后保留上一次预览，并明确提示当前预览已过期。
- 预览与发送共用颜色规则：单色为黑底红字，双色保留红、黄、绿；默认按 100% 像素显示，支持 25%–400% 缩放、适应窗口和滚动查看。
- 可使用当前状态或“未放学/放学中/已放学”示例状态预览。
- 无班级数据、配置错误和预览失败时显示明确原因。

### 4.8 本地操作日志

- 主界面在“接口日志”之外增加独立的“本地日志”入口。
- 记录软件启动/退出、刷卡与模拟刷卡、LED 时段切换、测试连接、测试画面、节目刷新及恢复结果。
- 不记录每秒时段轮询和正常翻页，连续相同日志 10 秒内合并，避免低配置主机产生高频磁盘写入。
- 日志按 1 MB 自动分卷，最多保留 7 个文件；页面只加载最近 500 条。

## 5. 展示规则

- 左侧标题可显示或关闭。
- 行标题显示年级名称。
- 列标题显示班级序号。
- 班级单元格显示当前状态：
  - `放学中`
  - `已放学`
  - 单色模式无状态时留空
  - 双色模式：未放学显示黄色，放学中显示红色，已放学显示绿色
- 年级和班级数据以服务端实际下发的数据为准，没有卡号的班级不推送到客户端，也不显示在 LED 屏上。

## 6. 核心流程

```text
开启测试模式 / 进入放学时段
        ↓
LED 服务激活
        ↓
读取本地班级目录和当天状态
        ↓
生成 LED 图片
        ↓
发送当前页
        ↓
按翻页间隔发送下一页
```

刷卡流程：

```text
班级刷卡 → 状态变为“放学中” → 启动倒计时
                         ↓
                  到期变为“已放学”
```

## 7. 非功能要求

- 控制卡通信继续使用仰邦 BX-6 系列 Java SDK。
- Windows 客户端运行时不弹出 Java 或命令行窗口。
- LED 通信失败不得阻塞刷卡、语音播报和服务端业务。
- LED 页面发送需避免并发覆盖，确保翻页、恢复原节目和状态刷新顺序正确。
- 配置修改后重启软件仍然有效。

## 8. 验收标准

1. 开启测试模式后，LED 屏在一个刷新周期内出现放学信息。
2. 刷卡后班级先显示“放学中”，达到设置的延迟后显示“已放学”。
3. 放学期间关闭并重新打开软件，已放学班级仍显示“已放学”。
4. 设置 3 个横向分区、每区 2 行后，六个年级按 2+2+2 生成一页。
5. 关闭测试模式并处于非放学时段，LED 屏恢复控制卡原有节目。
6. 点击“清空状态/恢复原节目”后，班级状态清空且动态画面停止。
7. 修改控制卡 IP、端口和 LED 版式后，重新启动软件配置仍保留。
8. 到达行政班放学开始时间时，如首次 LED 发送失败，网络恢复后 10 秒内自动重试并显示放学节目。
9. 测试模式下选择任一行政班执行“模拟刷卡”，能够听到语音，LED 状态先显示“放学中”再显示“已放学”，且服务端不产生放学推送。
10. “本地日志”可查询关键本地操作的成功或失败结果；软件待机时不会因每秒时段检测持续新增日志。
11. 进入测试模式后正式状态不显示但仍保留，退出测试模式后恢复。
12. 社团班刷卡和模拟刷卡能够触发独立的社团班 LED 页面。
13. 关闭标题后班级表格占用标题区域；修改手动像素尺寸后，预览图片和控制卡动态区域使用相同尺寸。
14. 配置页面可在不发送控制卡的情况下预览行政班、社团班和所有翻页内容。
15. 社团班可独立设置横向组数和每组行数；50个社团设置为5组×4行时生成3页。
16. 修改参数不会自动生成预览；点击“生成预览”时界面保持可操作，完成后可正常翻页和缩放。
17. 选择双色后，预览和真实 LED 均按“未放学黄、放学中红、已放学绿”展示；软件选择与控制卡屏参不一致时拒绝发送并说明修改方法。

## 9. 本期不包含

- 控制卡固件升级或网络自动配置。
- 自动读取控制卡像素尺寸。
- LED 屏硬件更换、亮度调节和物理线路排障。
- 服务端年级、班级和卡号绑定规则的重新设计。
- 自定义状态颜色编辑器；双色模式使用固定的红、黄、绿业务映射。
