# 窄屏多班级展示（beta.25）

当一个年级的班级列太多时，可按班级列分段，以保证表头、年级和状态一一对应。

## 使用入口

打开设置中的屏幕展示，选中需要设置的屏幕，在“行政班布局”选择：

| 布局 | 显示方式 | 适用条件 |
| --- | --- | --- |
| 常规 | 保持旧版本布局 | 当前内容已经能看清 |
| A：按班号上下分区 | 同一组年级按班级列分成多段，上下同时显示。每段都有班号表头和年级列 | 宽度有限，高度足够，希望同屏看全 |
| C：按班号分段轮播 | 一段占一页，页脚显示行政班页码及本页班号范围 | 宽度、高度都有限，可接受等待翻页 |

1. 将“每段班级列数”设为 7，可把 14 个连续班号分成 1～7 班、8～14 班。
2. “行政班每组年级数”设为 6，可将六个年级放在同一组。仍设为 2 则每两年级为一组，A/C 分别在各组内分段。
3. 如填写“轮播每页年级”，先按填写的年级组合分组，再按班级列分段。自定义年级顺序保留。
4. C 每页停留时间沿用“翻页间隔”。页码是行政班页面的页码，社团页面仍沿用原规则。
5. 点击“生成预览”，检查全部页面及实际字号。A 的字太小时改用 C，或减少每组年级数。分段功能不会增加实体屏像素。
6. 保存后应用到实际屏幕。使用“测试屏幕”可以检查当前草稿，测试节目会使用示例状态，请在非放学时段操作。

A/C 使用全宽内容区；旧“行政班横向分区”暂时禁用，切回常规后保留原值。单块屏幕的班级布局和每段列数独立保存，不会改变其他共用标题/字体方案的屏幕。电脑展示与 LED、设置预览、测试节目使用相同的分段规则。社团布局不受影响。

若 A 分区过多，连每个表头及年级行各一个像素都无法容纳，会拒绝生成并提示调整参数或改用 C，避免产生越界单元格。能够生成仍不代表文字足够清晰，需检查实际字号和现场显示。

## 班号和缺班规则

- “每段班级列数”是实际表头列数，不是最大班号。例如仅有 2、10、14 班，设为 2 列时分为“2班、10班”和“14班”。
- 数字班号按数值排列，名称班保留名称，排在数字班后面。每个年级在同组内共用相同表头。
- 某年级缺少对应班级时该格留空；即使某个年级在某段没有任何班级，仍显示年级行，避免其他年级错位。
- 状态始终按原班级 ID 和类型取值。分段不修改放学状态、刷卡、语音或平台上报。
- 若 C 某页包含名称班，页脚使用首尾班级名称作为范围提示，完整名称以表头为准。数据只有一段且仅一页时不额外占用页脚。

## 实现约定

采用两个屏幕设置：`led_class_layout`（`standard` / `stacked` / `carousel`），`led_classes_per_segment`（1～100，默认 7）。旧配置迁移默认 `standard`，不会自动切换布局。

已比较“渲染阶段直接截取每行的第 N 个班”和“布局阶段按表头分段”。选择后者：`build_led_page_layout()` 先复用年级分页，再按真实表头生成区域及 `region_headers`。A 将区域沿纵向排布，C 将各区域变成页面。这样年级班数不同时也不会错列，渲染器、预览、测试和输出不需要各自实现一套分页。

基线为远端 master `f2e5ffe`，先补入 beta.24 的独立提交 `3ef5857`（字号优化及其回归测试、版本元数据），再开发 beta.25。保留 master 的仓库清理，不恢复已清理的运行配置、Android POC 或个人文件，不引入 beta.23 的离线语音方案。

## 可复现验证

```bash
QT_QPA_PLATFORM=offscreen python -m pytest -q tests
python -m compileall -q src main.py tools/demo_led_segments.py
git diff --check
python -m tools.demo_led_segments /tmp/led-segments-proof --width 416 --height 240
```

示例脚本不连接控制卡、不读取学校数据，只生成六年级各 14 班的 A/C BMP 和 `metrics.json`。本地 macOS 字体下，416×240、顶部标题、每段 7 列时：A 一页两段，表格约 10 px；C 两页，表格约 14 px。该数值仅用于比较本示例，Windows 字体、屏幕尺寸和文案不同会改变结果，不能作为采购尺寸或实体屏可读性验收结论。

自动回归覆盖 84 班无遗漏/重复、非连续班号、名称班、缺班空格、末段不足、空目录、自定义年级分页、状态映射、标题位置、图片尺寸、C 页脚、配置合法性、旧配置迁移、每屏独立保存/重开、实际渲染及电脑输出。

## 现场验收

- 安装 beta.25，先保持常规布局，确认原学校数据、放学状态及显示正常。
- 选 A、每段 7 列、每组 6 年级，核对上区 1～7 班、下区 8～14 班，缺班空格准确。按实际学校目录调整参数。
- 选 C，检查 1/2、2/2 两页及班号表头，等待至少两个完整周期，确认每页停留时间正确。
- 在测试目录或非放学时段，分别验证 1、7、8、14 班的状态更新不会落入其他列。测试后恢复正式节目。
- 验证左右/顶部标题、单色/双色及自定义状态文案。多屏时分别设置 A/C，检查互不覆盖。
- 退出软件并重开，核对布局和每段列数仍保留。
- 从家长实际站位确认文字能读清。CI 测试和安装包构建不代替 Windows 启动、控制卡实际显示和现场可读性验收。

升级前备份安装目录下的配置和数据。回退到 beta.24 时选择常规布局；旧程序忽略新增字段，A/C 布局只有 beta.25 支持。
